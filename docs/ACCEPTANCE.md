# Alpha acceptance record

This is an engineering acceptance checklist, not scientific validation. Final observed results are recorded in TEST_RESULTS.md.

- Editable install and wheel include bundled discipline profiles and rubrics.
- CLI help, profile listing, fixture review, and a model-backed review work from a fresh output directory.
- A second run reuses successful stages; changed manuscript, rubric, model, or upstream output invalidates dependent work.
- Review modules actually receive the study map. Study identities and source identities remain stable in candidate records.
- Missing/unreadable inputs and partially extracted PDFs do not appear fully assessed. DOCX tables remain in document order.
- Quote anchoring accepts documented PDF normalization but rejects changed numerical values and wrong source IDs.
- Statistical consistency checks consider rounding and state their assumptions/coverage. Unsupported results do not count as passed.
- Unresolved criticisms, model-supported criticisms and recomputed numerical discrepancies remain distinguishable.
- Editorial decisions cannot upgrade factual support or invent findings; every rejection/merge has an audit record.
- Model subprocesses have no manuscript-triggered tool capabilities; requests are bounded by timeouts and schema validation.
- Reports visibly distinguish demo, partial and real complete runs, and escape manuscript/model content in HTML.
- Comparison fixtures verify order reversal, blinding, ties, per-paper aggregation and failure handling.
- Audit samples separate probability sampling from targeted cases. No precision statistic treats an unresolved model decision as truth.
- Corpus entries record original manuscript/review URLs, review round/version evidence, and eligibility; unknown versions cannot enter human comparison silently.
- Fable architecture and final code reviews have recorded dispositions.
