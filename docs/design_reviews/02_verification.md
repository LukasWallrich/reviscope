# Fable verification review

Review of the alpha checker, verifier, and profiles. Eight issues, ranked by how likely they are to produce a false claim in a real review.

**1. High. Two-tailed-only t-test and no detection of adjusted or one-tailed p.** In `checks.py`, the function `_p_value` computes only a two-tailed p for t. A correctly reported one-tailed p, a Bonferroni or Holm adjusted p, or a Greenhouse-Geisser corrected F gets `consistent=False` with the explanation "arithmetically inconsistent". That contradicts statistical_inference.generation.md, which says checker output is a lead. Fix: also compute the one-tailed p, scan the enclosing sentence for "one-tailed", "one-sided", "adjusted", "corrected", "Bonferroni", "Holm", "FDR", "Welch", "Greenhouse", and make the result tri-state. Report "consistent", "consistent only under one-tailed or adjusted assumptions", or "not reproducible under default assumptions". Soften the explanation string accordingly.

**2. High. De-hyphenation in `_normalize_with_offsets` corrupts offsets and breaks hyphenated quotes.** The regex substitution runs before the offset loop, so every recorded position indexes the modified string, not the caller's text. Any hyphen-newline removal shifts `start` and `end` in the returned `QuoteVerification`. Worse, real hyphens are deleted: "self-\nesteem" becomes "selfesteem", while the quote "self-esteem" keeps its hyphen, so a correct quote is marked "contradicted". Fix: handle hyphen-newline inside the loop by skipping the hyphen and following whitespace only when both neighbours are word characters, and compare with hyphens dropped from both sides. Also note the `_numbers` comparison in `verify_quote` is a tautology, since `find` is exact and the slice equals the needle.

**3. High. Quote-not-found maps to "contradicted" and overrides the model verdict.** In `verify_findings`, any failed anchor sets the whole finding to "contradicted" and discards the verifier's rationale. `verify_quote` does no curly-quote, apostrophe, or NFKC normalisation, and when `source_id` matches no supplied source it never searches the others. PDF text has "’" while model-written quotes have "'", so many legitimate findings will be rejected. Fix: add an "unanchored" quote status that yields `needs_review` or `downgraded` with the quote stripped, normalise quote marks, and fall back across sources while reporting the source mismatch.

**4. Medium. Zero-evidence findings can be "supported", and verifier quotes are never anchored.** A finding with an empty `evidence` list skips anchoring, so the model decision alone makes it "supported". `verifier_prompt` demands exact quotes from the verifier, but nothing runs `verify_quote` over `decision["evidence"]`. Both are hallucination paths into the final review. Fix: require at least one anchored quote for "supported", and anchor the verifier's evidence.

**5. Medium. The `_P` relation regex is a character class, not an alternation.** `[=<>&lt;&gt;]+` matches the individual characters `&`, `l`, `t`, `;`, `g`. A `rel` of "t" or ";" falls into the equality branch of `_consistent`. Replace with an explicit alternation such as `(?:<=|>=|<|>|=|≤|≥|&lt;=?|&gt;=?)`.

**6. Medium. Match window misses line breaks and can grab the wrong p.** `.{0,45}?` has no DOTALL flag, so any PDF line break between the statistic and its p kills the match. The lazy window also takes the nearest following p, which can belong to the next statistic in the same sentence. Fix: collapse whitespace before matching and stop the window at the next statistic head with a negative lookahead.

**7. Medium. Coverage counts are inconsistent with the patterns.** The `eligible` regex omits `X²(` while the chi2 pattern includes it, and `re.I` lets `\bt\s*\(` count prose like "T (". The `max(0, ...)` clamp hides the resulting overcount. Coverage numbers get reported as claims. Fix: derive `eligible` from the same head patterns used by `_PATTERNS`, and never clamp.

**8. Low. Rubric wording and extension mechanics.** measurement.verification.md says a generic-cutoff concern "is contradicted", conflating unsupported with refuted, against editorial.md's own line that status reflects evidential support. Change to "unresolved" and let editorial reject it. statistical_inference.verification.md's "exact quoted numbers must occur in the source" penalises legitimate recomputation, so scope it to numbers attributed to the source. In `load_profile`, `editorial_path` is hardcoded to the quantitative_social_science directory, so no child can override it. The `terminology` dictionary is never substituted into any prompt, so the education override is inert while prompts hardcode "participant". Appended child protocols carry no precedence statement over parent text.
