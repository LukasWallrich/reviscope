Does the Claude Code, Codex and OpenCode sandboxing make sense?

ReviScope orchestration review · branch orchestration-review · Codex CLI 0.169.0, Claude Code 2.1.322 · Linux tested live, macOS not tested · 16 November 2026

Answer

The addendum covers the OpenCode backend added afterwards.

Yes. The design protects the right things, and on Linux both CLIs enforce it. In live calls, neither sandboxed shell could read CLI credentials or anything else in the home directory, write outside its call directory, reach the network, or connect to local sockets such as D-Bus, systemd, gpg-agent or LXD. The weak points are not the shell rules themselves:

  • A timed-out Claude call left its sandboxed processes running. Ctrl-C during parallel stages waited for every running call to finish. Both are now fixed.
  • The shell can read everything outside the home directory, including /tmp and mounted drives. The README now says so.
  • Three gaps need a decision: on macOS, whether the sandboxed shell can read credentials from the login Keychain (untested); an ANTHROPIC_API_KEY in the environment can switch Claude runs to metered API billing; and Claude's WebFetch runs on the user's machine and can reach local and intranet HTTPS hosts.

The two usability costs, needing a Codex binary outside $HOME on Linux and Python/R packages installed system-wide, follow from the home-directory rule. Codex 0.169 cannot re-allow read-only access to a path under a denied home: I tested this, and only a write grant takes effect. Write access would let the model modify the Codex binary, so the Codex requirement stays.

Findings, ranked

fixed1. Timed-out Claude calls left the sandboxed shell running

Claude Code starts its Bash sandbox (bubblewrap, proxy helpers and the command itself) in a session of its own. Killing the CLI's process group missed it. In a live call with a 75-second timeout, the sandbox wrapper and a sleep 400 were still running 110 seconds later. In real runs that would be an R or Python job, or a stuck command, outliving its stage. Codex did not leave processes behind.

Change: on timeout or interrupt, ReviScope snapshots the process tree with ps (works on Linux and macOS) and kills every descendant and its process group. Re-tested live: nothing left. New test: test_timeout_also_kills_children_that_left_the_process_group.

fixed2. Ctrl-C during parallel stages waited for running calls

With --parallel above 1, Ctrl-C reached only the main thread. The thread pool then waited for every running CLI, which can take up to the per-call timeout (default one hour). Those CLIs run in their own sessions, so the terminal's interrupt never reached them and they kept using quota.

Change: on interrupt, queued stages are cancelled and every running CLI is killed with its process tree. New test: test_interrupt_during_parallel_stages_stops_every_running_cli.

needs decision3. macOS: the Keychain is outside the home-directory rule

On macOS, Claude Code stores its login in the login Keychain, not in a file. Hiding ~ blocks the Keychain file but not the security command, which asks the system Keychain service. Whether the sandbox lets the shell reach that service, and whether the Keychain prompts, I could not test without a Mac. If both allow it, the main credential guarantee fails on the platform most users have. Codex keeps ~/.codex/auth.json as a file by default, which the rule covers.

Recommendation: run this once on a Mac through the Claude backend (the probe script asks the model to run it in its shell), and add the result to the README.

security find-generic-password -s "Claude Code-credentials" >/dev/null 2>&1 && echo KEYCHAIN_READABLE || echo keychain-blocked

If it prints KEYCHAIN_READABLE, block the Keychain service in the sandbox settings, or refuse tool-enabled Claude calls on macOS until it is blocked.

needs decision4. ANTHROPIC_API_KEY can switch Claude runs to metered billing

The environment allowlist passes ANTHROPIC_API_KEY to Claude Code. Many researchers who script have one set. Claude Code can then authenticate with the key instead of the subscription login, so a long review is billed per token instead of drawn from the subscription, with no warning. The README says calls "use your CLI authentication". The key no longer reaches Codex, which never needed it.

Recommendation: stop passing ANTHROPIC_API_KEY by default. Add an explicit opt-in (--claude-auth api-key) and record which login was used in review.json. CLAUDE_CODE_OAUTH_TOKEN (subscription) can stay.

needs decision5. The shell can read everything outside the home directory

Both shells could list and read /tmp. That includes other tools' scratch directories (on this machine, Claude Code's per-session scratchpads) and the staged page images of other ReviScope calls running at the same time. Mounted drives (/data here; /Volumes on macOS) are readable too. The README previously implied that only the call directory mattered; it now says what stays readable.

Recommendation: also deny /tmp and /var/tmp, keeping the call directory readable. For Codex on Linux I verified that a "/tmp"="deny" entry still leaves the workspace under /tmp writable. Claude needs denyRead on /tmp plus allowRead on the call directory. This changes the command line, so every cached stage is rerun once, and macOS (/tmp → /private/tmp, per-user $TMPDIR) needs testing first. Denying removable drives by default is a judgement call; I would document rather than deny.

needs decision6. Claude WebFetch can reach local and intranet HTTPS hosts

Claude's WebFetch runs on the user's machine, not on Anthropic's servers. A live fetch of http://127.0.0.1:18765/ reached the local test server; it failed only because WebFetch upgraded the request to HTTPS. A university intranet page, router admin page or local HTTPS service would be fetched and shown to the model. Codex's web search runs on OpenAI's side and cannot reach the user's network.

Recommendation: add deny rules for localhost, loopback and private address ranges to the Claude settings. Bundle this with finding 5, since both change the Claude command line and invalidate Claude caches once.

implemented6a. The offline shell blocked data recomputation, and models kept trying

Across 1,725 stored stage records, the shell tried the network (curl, urllib, package installs) in 472 of 877 Codex stages and 492 of 642 Claude stages, 1,750 attempts in all, every one refused. The models then used the fetch tools, which work for metadata: OSF, Crossref, OpenAlex, PubMed and doi.org pages were fetched thousands of times. But fetched content never reaches the shell, and Claude's WebFetch returns a summary written by a smaller model, not the raw file. Raw OSF file links also redirect to another host, which WebFetch does not follow automatically. In practice, data and analysis scripts from OSF or Zenodo cannot be recomputed.

Change, linked materials (on by default): before review, ReviScope downloads the OSF, Zenodo, figshare and GitHub repositories that the sources link, outside the sandbox. Limits are 25 MB per file and 100 MB and 200 files per run. Files are hashed in materials/manifest.json, reused on rerun, and copied read-only into every review and verification call, with an index in the prompt. Files whose names suggest peer-review correspondence or another version of the manuscript, OSF preprints, and audio or video are skipped and listed in the audit record. --no-materials turns this off. Live check: an OSF project (21 files, 11 MB) downloaded in about 2 minutes, and both CLIs computed 937 rows × 156 columns from a staged spreadsheet, which matches a direct check.

Change, --shell-network (off by default): the shell may reach a fixed list of scholarly APIs, data repositories and package indexes, and nothing else, loopback and the local network included. Claude enforces the list with allowedDomains. Codex enforces it only with the experimental features.network_proxy=true flag plus a domains = {host = "allow"} map; the older allowed_domains key is ignored silently, even under --strict-config, which is why the earlier test reached example.com. Verified live for both CLIs: Crossref 200, example.com blocked, a local test server blocked (Codex). Under Codex a blocked request ends that shell command. A test guards against the ignored key. The audit cannot list what the shell itself downloads.

For comparison: coarse (coarse-ink 1.9.6) gives its CLI calls no shell and no web search at all, denies /tmp, and runs literature search itself, outside the model (arXiv API, or Perplexity through OpenRouter). Not done: option (a), telling the model in the prompt that the shell is offline. The materials index already says to use the staged copies; a general note would change every prompt and rerun cached stages.

fixed7. Relocated CLI config directories were readable

The shell rule hid only $HOME. A user with CODEX_HOME or CLAUDE_CONFIG_DIR outside the home directory (common on shared servers) exposed the credentials stored there.

Change: such a directory is now denied as well (Codex profile, Claude denyRead and a Read deny rule). CLAUDE_CONFIG_DIR is passed to Claude so relocated logins work. Command lines are unchanged when these variables are unset or point inside home.

fixed8. Missing CLIs and unsafe policies were found mid-run

An earlier owner run lost all four verification batches to FileNotFoundError after discovery had finished. The verifier CLI was only looked for when verification started.

Change: before the first stage, a run checks that each selected CLI is installed, that the managed policy is acceptable and, for Codex on Linux, that a binary outside home exists. The CLI prints a one-line error and exits with code 1. The Codex message now names an install command.

fixed9. Managed-policy detection missed drop-in files

Claude Code 2.1.322 merges managed-settings.d/*.json drop-ins (confirmed in the binary). The check read only managed-settings.json. Codex user-level requirements.toml was looked for in ~/.codex even when CODEX_HOME pointed elsewhere.

Change: both are now checked and included in the policy hash. Still not covered: macOS configuration profiles (MDM), server-delivered managed settings, and /etc/codex/config.toml, which Codex loads as a system layer and which could add MCP servers. Recommendation: for Codex, replace the file check with a behavioural canary once per run. codex sandbox -P reviscope runs the real permission profile without a model call and can confirm that home, network and sockets are blocked. Claude has no model-free equivalent, so its file check stays.

needs decision10. Usability: toolchains in the home directory are invisible

conda/miniforge, uv-managed Python, pyenv, renv and user R libraries (~/R, ~/Library/R) all live under home, so recomputation in the shell only sees system-wide installs. The model then works around missing packages or estimates instead of computing. Codex cannot grant read-only access under a denied home, so a per-user "allow my conda" option is not possible for Codex without giving the model write access.

Recommendation: add a reviscope doctor command that runs python3 -c "import scipy, statsmodels, pandas" and Rscript -e 'library(lavaan)' inside the real Codex sandbox (free with codex sandbox) and prints exactly what to install. That beats discovering it from tool errors mid-review. Longer term, a ReviScope-managed environment outside home (for example under /opt/reviscope) would give every reviewer the same packages.

needs decision11. A schema failure reruns the whole tool-enabled stage

When output fails validation, the repair call repeats the full task with tools, which roughly doubles a 10–20-minute stage. Codex constrains output with --output-schema, so this mostly affects Claude. Claude Code 2.1.322 supports --json-schema, which ReviScope does not use.

Recommendation: pass --json-schema to Claude, and make the repair a tool-free reformatting call with the previous output. Both change model behaviour and Claude cache keys, so evaluate them in specialist mode first.

note12. Cache identity depends on which variables happen to be set

The backend identity hashes the names of allowlisted variables present in the environment. Running once with LC_ALL or a proxy set and once without changes every cache key. The identity was left unchanged here so existing caches stay valid (checked: identical for all four backend configurations in this environment).

Recommendation: hash the allowlist itself instead, at the next deliberate cache invalidation. Bundle it with findings 5, 6, 11 and 13.

note13. Cost and time are not recorded per stage

From recent run logs: 17–37 model stages per review, 230–550 tool calls, 60–186 minutes of summed stage time, 21–70 minutes wall-clock at --parallel 4, and single stages up to 21 minutes. Codex's turn.completed event carries token counts, and Claude's result event carries tokens and total_cost_usd. ReviScope discards both. There is no automatic retry for transient failures (rate limits, network): the stage fails, the run is marked partial, and rerunning the same command resumes from cache. That is a sound default for subscription quotas.

Recommendation: store usage in the stage provenance and print a per-run total, so users see what a review costs against their quota. In the same cache-invalidating change, add --disable hooks to the Codex command so administrator hooks cannot run during review calls.

What was verified

  • Live calls through both backends (Codex gpt-6-luna at low effort, Claude claude-opus-5-5 at low effort) ran a probe script. Credentials unreadable, home hidden, writes outside the call directory refused, no network, Unix-socket connects refused, /tmp readable, system SciPy visible. The probes ran again after the changes.
  • Model-free checks with codex sandbox using the exact ReviScope permission profile: D-Bus, systemd, gpg-agent, LXD and T3 sockets all refused. A read grant under a denied home is ignored, and only a write grant takes effect.
  • Codex's image tool refuses files under home. Claude WebFetch reaches 127.0.0.1.
  • Orphan test before and after the fix (Claude leaked processes before and none after; Codex leaked none either time).
  • uv run --extra dev pytest -q: 399 passed, 10 skipped. The two new process tests fail against the old kill logic.
  • No manuscript text was used. Probes used empty evidence.

Not verified: anything on macOS. The CLI flags used were checked against --help for the installed versions.

Addendum: the OpenCode backend

Branch opencode-backend · OpenCode 1.19.5 · bubblewrap 0.9.0 · tested live with DeepSeek V4 Flash through OpenRouter · Linux tested live · 16 November 2026

Answer. OpenCode keeps the design's guarantees for the shell on Linux, but only because ReviScope supplies the sandbox. OpenCode 1.19.5 has permission rules (allow, ask or deny per tool, with patterns) and no operating-system sandbox: its bash tool runs commands as the user, with OpenCode's full environment, including the OpenRouter key. ReviScope therefore points OpenCode's shell setting at a wrapper that runs every command in bubblewrap, and denies the file tools, which run inside OpenCode itself. Two things fall short of the Codex and Claude backends: no --shell-network, and no tool-enabled calls outside Linux. Any model OpenCode lists can be used; page images are attached when the model accepts images.

What OpenCode offers (read from --help and the v1.19.5 source)

  • Non-interactive mode. opencode run --format json reads the prompt from stdin and prints one JSON event per line. Permission requests that would ask are rejected automatically unless --auto is passed, which ReviScope never does. A session error sets exit code 1.
  • Tool-call provenance. Each finished tool call arrives as a tool_use event with the tool name, input, output, status and, for bash, the exit code. ReviScope records these as ToolCalls. A call still running at a timeout is not printed, so it leaves no record (Codex and Claude record it as incomplete).
  • Configuration. OpenCode merges the global config (~/.config/opencode), OPENCODE_CONFIG, project files and .opencode directories found upward from the working directory, OPENCODE_CONFIG_CONTENT, remote and organisation configs tied to stored logins, and finally a managed config (/etc/opencode, macOS MDM). It also reads AGENTS.md and ~/.claude/CLAUDE.md, skills and plugins, and keeps sessions in a database under ~/.local/share/opencode, next to auth.json.
  • Tools. bash, read, edit, write, glob, grep, list, task (sub-agents), skill, todowrite, webfetch and websearch. Web search is off for third-party providers unless OPENCODE_ENABLE_EXA is set; it then queries Exa's public MCP endpoint. Web fetch runs in the OpenCode process on the user's machine.
  • Images and structured output. --file attaches files. OpenCode reads them itself, without a permission check, and passes images to models whose catalogue entry accepts image input; ReviScope attaches page images only then, and stops the call otherwise. opencode run has no output-schema option, so ReviScope parses JSON from the final text and uses its existing repair call.
  • Models and credentials. Any provider/model from opencode models is accepted. Before the run, ReviScope reads OpenCode's catalogue (models.opencode.ai) for the provider's credential variables and asks an isolated opencode models PROVIDER --verbose for the model's reasoning variants and input modalities. Only that provider's variables, and its entry from auth.json (passed in OPENCODE_AUTH_CONTENT), reach OpenCode. The default model is openrouter/z-ai/glm-5.3-flash, which accepts images.
  • Model choice. OpenCode names a session with a separate call to a "small model", which for OpenRouter defaults to a small Anthropic or OpenAI model. ReviScope sets small_model to the selected model, whitelists only that model for the provider, and passes --title so the naming call is skipped.

Design chosen

Of the candidate designs, I chose to wrap the shell, not the whole OpenCode process. Running OpenCode itself under bubblewrap does not separate the shell from what OpenCode needs, the API key and the network, because the shell inherits both. Disabling the shell would lose recomputation, which the review relies on. Routing commands through codex sandbox would make OpenCode users install Codex. Bubblewrap is already present wherever Claude Code's sandbox works on Linux.

Gaps

needs decisionO1. Web fetch reaches local hosts through host names

As with Claude's WebFetch (finding 6), OpenCode's web fetch runs on the user's machine. The deny rules catch literal loopback and private addresses (http://127.0.0.1:… was refused live), but http://localtest.me:…, a public name that resolves to 127.0.0.1, fetched a page from a local test server. Redirects are not checked either. Closing this needs a filtering proxy for OpenCode's own traffic.

Recommendation: decide together with finding 6; until then the README states the gap.

fixedO2. Page images and truncated output

The first version accepted only DeepSeek V4 Flash, which reads text only, so PDF reviews through OpenCode ended partial. ReviScope now accepts any model OpenCode lists and attaches page images when the model accepts them. A text-only model still stops a call that needs page images.

OpenCode cuts tool output at 2,000 lines or 50 KB, saves the full text in its data directory and tells the model to open it with the read or grep tool, both disabled here. That directory is now mounted read-only in the sandbox, and the review prompt for OpenCode says to read files, including saved output, with shell commands. Live check: asked to print 200,000 lines without redirecting them, the model read line 150,000 from the saved file with sed. Without that instruction to print, it had redirected the output to a file itself.

Live check with GLM 5.3 Flash (openrouter/z-ai/glm-5.3-flash, the default): given only a page image of examples/table_mismatch, a synthetic PDF whose Table 1 contradicts its text, the model read two of three requested cells correctly (4.61 and 0.71) and misread the third (4.09 for a printed 5.42). In a full review of that PDF, page images were attached to the verification and table-reading stages, and the contradiction between Table 1 and the text was published as the critical finding. The first run ended partial on two output-format problems. In one verification batch, a bracketed interval in the prose before the JSON answer was taken as the answer; ReviScope now uses the first embedded JSON value that matches the schema. The editorial stage left out 21 of 55 finding IDs and returned one unknown ID; batched calls now get one retry that lists every missing, duplicate or unknown ID, and a second violation still fails the stage. Rerun from cache with both changes, the two stages completed and the review was complete.

gapO3. No --shell-network, Linux only, no record of unfinished calls

bubblewrap can remove the network but cannot allow a list of hosts, so --shell-network is refused for OpenCode. On macOS, tool-enabled OpenCode calls refuse to run (no sandbox-exec profile was written or tested); tool-free calls work. A tool call cut off by a timeout leaves no record. OpenCode extracts its native libraries into the call directory, where the shell can read them; they contain nothing private.

noteO4. Free OpenCode models and training on submitted text

OpenCode offers fairly capable models free of charge for limited periods (the opencode/…-free models). The price is often the data. According to the Privacy section of OpenCode's Zen documentation on 16 November 2026, Big Pickle, Iceman Free, Inkling 2 Small Free, Flint 40B Free and MiMo-V2.6-Flash Free retain submitted text during their free period and may use it to improve or train the model, and NVIDIA's free Nemotron endpoints are for "trial use only — do not submit personal or confidential data". GLM-5.3-Flash Free, DeepSeek V4.1 Flash Free, MiniMax M3.1 Flash Free, Hy4 Flash Free and LongCat 2.5 Free (hosted in China) are described as zero-retention with no training use, and Beam Free as retaining inputs for 30 days without training. These terms change as free periods begin and end, and the documentation shipped with OpenCode 1.19.5 already listed different models. An unpublished manuscript should go to a free model only after checking that model's current entry; ReviScope does not check it.

Verification

  • Model-free: the generated wrapper, run exactly as OpenCode runs it (wrapper -c COMMAND) with the OpenRouter key in its environment, blocked reading auth.json and ~/.codex/auth.json, listing home, seeing the key, writing to /usr/local or a staged material, seeing OpenCode's state, HTTPS and raw TCP, creating a Unix socket or connecting to one in the call directory, the D-Bus socket, host processes, other /tmp files and io_uring_setup. Writing in the call directory, loopback TCP inside the sandbox, socketpair, SciPy and R worked.
  • Live probe (one call, empty evidence): the model ran the same probe through OpenCode's bash tool with identical results; PubPeer and 127.0.0.1 fetches were refused; the localtest.me fetch got through (O1); Exa search returned the PubMed record for Cohen (1992); all eight tool calls were recorded.
  • End to end: a synthetic Markdown paper written for this test (no manuscript text), reviewed with --effort high --no-metacheck --no-materials, completed all 21 model stages in about 37 minutes of wall-clock time at --parallel 4, with 219 recorded tool calls (170 shell, 37 search, 11 fetch, and one call to the denied read tool, recorded as refused). The planted error was found: the review recomputed the p-value with SciPy in the sandbox and reported p = .002 for t(118) = 2.10 as wrong (p ≈ .038), which was published as the only critical finding. eval/audit_tool_use.py rated the run clean.
  • Offline tests: event parsing, configuration isolation, permissions, sandbox arguments, the seccomp program (interpreted in the test), managed-config refusal and a model-free sandbox run. uv run --extra dev pytest -q: 412 passed, 10 skipped.
  • Denied tools cost little: of the 219 tool calls in the end-to-end run, one was an attempt to call an unavailable tool; the other eight failures were ordinary shell or Python errors.
  • Spend, from OpenRouter's key usage: DeepSeek V4 Flash cost US$0.003 for the probe, US$0.40 for the end-to-end review (including a run that I stopped and resumed from cache) and US$0.01 for two truncation probes, US$0.42 in all. The GLM 5.3 Flash image probe and PDF review (about 240 tool calls) had added no charge to the key's usage by the end of the session; at the listed prices of US$0.04 per million input and US$0.08 per million output tokens they should cost a few cents.
